# Verification and release status

Hermes PR #116246 motivates the acceptance gates: compaction must retain useful evidence within a measured budget, not merely pass scoring helper tests. This report separates executed checks from outstanding product requirements. The clause-by-clause map is in [compliance.md](compliance.md).

## Executed locally

- 127 tests pass on `1.0.0-rc.4`. `mypy` passes for 14 source files. `black --check` reports 38 files unchanged. Non-vendored coverage is 97.45%, 688 of 706 statements. `python -m build` produces a wheel and a source distribution, `jev_lcm_hermes_compaction-1.0.0rc4-py3-none-any.whl` and `jev_lcm_hermes_compaction-1.0.0rc4.tar.gz`.
- Calibration and provider parity: identical JSON scenarios with Python-generated golden results are checked by both languages, covering missing keys, single-provider operation, rate-limit fallback, cooldown expiry, pinned-provider failure, malformed payloads, low-score calibration, minimum samples, cap, and conservative mode.
- The evaluator runs three arms through actual engine code with synthetic external transports: `production-equivalent` (host default condensation), `jev-only` (Jev ranking with no summary path), and `jev-lcm` (the shipped design). `evaluation/results.json` records `synthetic-transport-integration`, `upstream_transcripts_available: false`, and `upstream_production_run_reproduced: false`. At a 2000-token budget the production-equivalent arm retained 0 of 2 fixture markers in the assembled context and the jev-lcm arm retained 2 of 2, both at 52655 input tokens; the jev-only arm retained 2 of 2 but grew the prompt to 52749 tokens and did not meet the budget, which is the unbounded text floor from PR finding #3 reproduced in a measurement. Raw retrieval recovered the marker in both arms that own a store.
- A disposable home install copied the built wheel into an isolated target directory, ran real plugin discovery, registered `jev-lcm` as the context engine, ingested evidence, recovered it with `lcm_grep`, and reset cleanly.
- Install discovery was re-executed against the host loader on 2026-09-21 through both routes. Entry-point route: the built wheel installed into an isolated target, the plugin discovered with `source: entrypoint`, `enabled: true` after the allow-list, engine `jev-lcm` registered. Directory route: `<HERMES_HOME>/plugins/jev-lcm/` with `plugin.yaml`, `plugin.py`, and `__init__.py`, discovered with `source: user`. `hermes plugins enable jev-lcm` was executed against a disposable home and wrote `plugins.enabled: [jev-lcm]`; `hermes plugins disable jev-lcm` wrote `plugins.disabled: [jev-lcm]`.
- Fresh-profile provider acceptance ran three times in disposable homes, one per key configuration, each through real discovery, ingest, `lcm_grep` recovery of a synthetic identifier, and reset: `OPENROUTER_API_KEY` only selected `['openrouter']`, `TYPESAFE_API_KEY` only selected `['typesafe']`, and both keys selected `['typesafe', 'openrouter']`. Each run stored two raw rows and recovered the marker.
- The `laya_then_hosted` route was exercised live on 2026-09-26 through `evaluation/live_laya_then_hosted.py` against the `laya-serve` on `http://127.0.0.1:8123`. The chain built as `["laya", "typesafe", "openrouter"]` and the local hop answered over real HTTP: `last_provider: laya`, `fallback_count: 0`, `calls: 1`, score `0.2966`, no hosted URL reached. Pointing the local hop at a closed port then produced a real connection refusal and the chain moved to `https://api.typesafe.ai/v1/systemone` and then `https://openrouter.ai/api/alpha/decisions`, with `fallback_count: 2` and `last_errors {"laya": "transport_error", "typesafe": "transport_error", "openrouter": "transport_error"}`. Those hosted requests were recorded rather than sent. No hosted API key exists on this machine, so the hosted leg rests on `tests/test_laya_then_hosted.py` and on no live hosted call.

## Executed locally for `1.0.0-rc.4`

- The consecutive-failure breaker, live. The same probe's third phase kept the local hop on the closed port with `jev_fallback_cooldown_s: 0`, answered the hosted hops from a local recorder, and drove four consecutive local failures. Three hosted fallbacks answered over the recorded URL `https://api.typesafe.ai/v1/systemone`; the fourth attempt terminated with the local `transport_error` and reached no hosted URL, and the process counter read `4`. That is the suppression the unit tests describe, over real connection refusals on the local hop.
- The mode aliases, live. The probe's fourth phase built both vocabularies: `laya_local` produced `["laya"]` and `same_chain: true` against `laya`, `laya_with_jev_fallback` produced `["laya", "typesafe", "openrouter"]`, and `jev_api` produced `["typesafe", "openrouter"]`. Unit coverage is in `tests/test_laya_mode_aliases.py`, including the rejection of an unknown value with the accepted names in the message.
- Breaker unit coverage: `tests/test_laya_fallback_breaker.py`, eight tests over three consecutive fallbacks and a suppressed fourth, no remote call on the suppressed attempt, the reset on a healthy local call on both the fallback and the plain local paths, the per-process lifetime, the counter in diagnostics, and the category-only warning.
- Logging audit. Every log, warning, and print call in this package's own modules, excluding the vendored LCM snapshot, was inspected. The eight calls that run on or beside the scoring path format a static message, a provider name, a `ProviderError` reason drawn from a fixed set and clamped to `transport_error`, a counter, or the hardcoded failure limit. None can carry the request, the state, candidate text, a question instruction, or an answer. `tests/test_fallback.py` drives a batch whose state and candidate text carry a sentinel and asserts the sentinel never reaches `caplog`; `tests/test_laya_fallback_breaker.py` does the same for the suppression warning. The bundled `jev-lcm` CLI prints provider diagnostics and a synthetic probe result only, and the vendored LCM snapshot is unchanged upstream code.

## Not established

- Local Laya quality on any population. This repository's own probe covers eight spans. The strongest available comparison is the matched 100-question, three-mode benchmark published with the DOGA fork: goal agreement 56/100 for local Laya against 88/100 for the hosted Jev API, response mode 41 against 68, stakes 37 against 67, high-versus-low ambiguity 67 against 87, and none of the 30 authored high-ambiguity labels detected locally at the 0.7 threshold. It was run in another repository against an authored, subjective label set, and no final-answer quality was scored anywhere.
- The breaker's downstream effect. It bounds repeated remote egress after local errors and nothing more. It cannot detect a valid yet incorrect local judgment, and no threshold was tuned on the benchmark set.
- The production recall-at-budget comparison. The upstream transcript, provider and model identities, and the upstream evaluation policy were never supplied, so no production number is asserted anywhere in this repository.
- Continuous integration on a later commit than the one under review. The `Tests` workflow was read back as `success` for every pushed head: `fd9d471` (run 35636485852), `37cf192` (35636650091), `fb08f11` (35637318780), and `0e15b2d` (35637532979).
